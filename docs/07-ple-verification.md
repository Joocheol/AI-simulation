# 07 · PLE 제약 검증 프로토콜

> **이 검증은 모델 제작 착수 전에 수행합니다.** 소요 약 30분.
> 결과에 따라 [03 · 모델 시간 축](03-running-case.md#2-모델-시간-축--트랙-a--b)의 **트랙 A / B가 확정**되고, 트랙 B일 경우 모든 모델의 시간 단위·차트 축·워크북 환산표를 다시 만들어야 합니다.
> **0.5일을 아끼려다 4일을 재작업하게 됩니다.**

---

## 1. 검증이 필요한 이유

AnyLogic PLE의 모델시간 제한은 다음과 같이 알려져 있습니다.

> 모델 시간은 **1회 실행당 5시간**으로 제한되며, **Process Modeling Library를 사용하는 모델은 예외**입니다.

그런데 이 문장에는 **설계를 좌우하는 두 가지 모호함**이 남아 있습니다.

| 모호함 | 왜 중요한가 |
|---|---|
| **면제 조건** — "PML을 사용한다"가 *블록이 존재하기만 하면*인가, *실제로 개체가 통과해야*인가? | M3~M5(3~7일 모델시간)의 성립 여부가 여기 달려 있습니다 |
| **복제 합산** — 제한이 *복제당*인가 *실험 전체 누적*인가? | 누적이면 **M2(1,000복제)가 통째로 막힙니다** |

두 번째는 특히 간과되기 쉽습니다. 몬테카를로는 "모델시간 1,000틱"이 아니라 "복제 1,000회"이므로 직관적으로는 무관해 보이지만, 제한이 합산으로 계산된다면 실습2 전체를 재설계해야 합니다.

---

## 2. 검증 항목 T1 ~ T4

각 테스트는 최소한의 빈 모델로 수행합니다. 실제 러닝 케이스 모델을 쓰지 마십시오 — 변수가 많아 원인 분리가 안 됩니다.

### T1 · 비-PML 모델에 제한이 걸리는가

| 항목 | 내용 |
|---|---|
| **모델** | 빈 모델 + 주기 이벤트 1개 |
| **설정** | 시간 단위 = **일(DAY)**, 정지 시간 = **30** |
| **확인** | ① 제한이 실제로 걸리는가 ② 걸린다면 **어떤 방식으로** — 실행 중단 / 경고 표시 / 정지시간 강제 하향 |

> 걸리는 방식이 중요합니다. **조용히 정지시간을 잘라버리는 경우** 수강생은 "다 돌았다"고 믿고 잘못된 결과를 해석하게 됩니다. 이건 교육적으로 가장 나쁜 실패 양상입니다.

### T2 · PML 면제 조건 — **가장 중요**

| 항목 | 내용 |
|---|---|
| **모델** | T1 + `Source → Sink` 블록 한 쌍 (연결만, **도착률 0**) |
| **설정** | T1과 동일 |
| **확인** | **블록이 존재하기만 해도 면제되는가**, 아니면 실제로 개체가 통과해야 하는가 |
| **추가** | 도착률을 0이 아닌 값으로 바꿔 재실행 후 비교 |

**이 결과가 트랙 A / B를 결정합니다.**

### T3 · 제한의 계산 기준

| 항목 | 내용 |
|---|---|
| **모델** | T1에서 시간 단위만 **초(SECOND)** 로 변경, 정지 시간 = 30 |
| **확인** | 제한이 **모델 시간의 절대량**(5시간 = 18,000초)으로 계산되는가, 아니면 시간 단위와 무관한 틱 수인가 |

트랙 B의 기술적 성립 여부가 여기서 판가름납니다.

### T4 · 몬테카를로 복제 합산 여부 — **숨은 리스크**

| 항목 | 내용 |
|---|---|
| **모델** | Monte Carlo 실험, **1,000 복제**, 복제당 모델시간 1틱 |
| **확인** | 제한이 **복제당**인가 **복제 합산**인가 |
| **영향** | 합산이면 **M2를 재설계**해야 합니다 (복제 수 축소 또는 복제당 모델시간 0으로 재구성) |

## 3. 함께 확인할 항목

검증 세션에서 한 번에 처리하십시오. 각각 커리큘럼의 특정 부분에 직결됩니다.

| # | 확인 항목 | 영향받는 설계 |
|---|---|---|
| A1 | **결과 내보내기**(Excel/CSV export) 가능 여부 | 실습5 비교표 작성 방식 — 불가하면 **종이 워크시트 수기 기록**으로 전환 |
| A2 | PLE로 만든 파일을 다른 에디션에서 열 수 있는가 | 교육 후 사내 전용 경로 · 후속 PoC |
| A3 | 애니메이션 비활성화 옵션 위치 | 템플릿 기본값 고정 · 워크북 기술 |
| A4 | JVM 메모리 상한과 변경 방법 | 예금자 population 상한 재확인 |
| A5 | 라이선스 활성화가 **오프라인으로 가능한가** | **망분리 대응** → [05 · 2.1](05-operations-and-license.md#21--망분리網分離-환경--국내-금융권-최대-리스크) |
| A6 | 8.9.x 최신 패치 버전과 설치 파일 크기 | 사전 설치 안내서 |

> **A5는 망분리 리스크(R3)의 핵심**입니다. 오프라인 활성화가 가능하다면 대응 난이도가 크게 낮아집니다.

## 4. 트랙 결정 규칙

```
T2 통과 (블록 존재만으로 면제)  ─┬─ T4도 복제당 계산 ──→ 【트랙 A】 그대로 진행
                                 └─ T4가 합산 계산 ────→ 【트랙 A】 + M2 재설계
T2 실패 (개체 통과 필요 / 면제 없음) ──────────────────→ 【트랙 B】 전면 적용
```

| | **트랙 A (권장)** | **트랙 B (폴백)** |
|---|---|---|
| 시간 단위 | 분 (MINUTE) | 초 (SECOND) |
| 규약 | 없음 (실시간 그대로) | **1틱 = 현실 1분** |
| 총 모델시간 | 7일 = 10,080분 | 18,000틱 = 현실 12.5일 |
| 추가 작업 | 없음 | 차트 축 재라벨링, 블록 단위 드롭다운 고정, 워크북 환산표, **강사 대본 용어 교체** |

트랙 B의 상세 완화책은 [03 · 2.3](03-running-case.md#23-트랙-b-폴백--t2-실패-시)에 있습니다.
