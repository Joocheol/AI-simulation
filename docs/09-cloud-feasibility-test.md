# 09 · AnyLogic Cloud 실습 환경 타당성 테스트 (C1~C4)

> **목적:** AnyLogic Cloud(브라우저)를 본 과정의 **주 실습 환경**으로 쓸 수 있는지 판정한다.
> **소요:** 약 30분. **필요한 것:** AnyLogic Cloud 무료 계정, 브라우저, 스톱워치(휴대폰).
> **결론이 바꾸는 것:** 통과하면 [05 · 2.1 전산실 복원 솔루션](05-operations-and-license.md#21--학교-전산실-복원-솔루션--이-형태의-최대-리스크)과 [05 · R4 학교 방화벽](05-operations-and-license.md#5-리스크-레지스터) 리스크가 **통째로 사라집니다.** 설치할 것이 없어지기 때문입니다.

---

## 0. 왜 지금 테스트하는가

**AnyLogic 9 웹 에디터가 Cloud 등록 사용자 전원에게 열렸습니다.** 브라우저에서 모델을 만들고, 컴파일하고, 실행하고, 실험까지 돌립니다. 데스크톱 설치가 불필요해집니다.

그런데 두 가지 걸림돌이 있습니다.

| 걸림돌 | 확인 방법 |
|---|---|
| 아직 **Technology Preview** — 안정판은 데스크톱 8.9.9 | C1로 실제 만들어 보고 판단 |
| 무료 계정의 **실행 시간 제한** (벽시계 기준) | C2 · C3 |

무료 계정 공표 제한:

| 실행 유형 | 무료 한도 |
|---|---|
| 애니메이션 **없는** 단일 실행 | **1분** |
| 애니메이션 실행 | 5분 |
| 멀티런(복제) 실험 | **5분** |

> ⚠ **모델 시간이 아니라 실제 경과 시간(벽시계)** 기준입니다. 이것이 이 테스트의 핵심 변수입니다.

### 테스트 순서와 의존관계

```
C1 (모델을 만들 수 있는가)
      ↓ 성공하면 같은 모델을 그대로 재사용
C2 (7일치가 1분 안에 도는가)  ──→ 통과하면 C4는 자동 통과 (아래 C4 참조)
      ↓
C3 (20복제가 5분 안에 도는가)  ←── M5의 생사가 여기 달려 있음
```

> 📌 **C1·C2·C4는 같은 모델 하나로 처리합니다.** 새로 만들지 마십시오.

### 표기에 관한 주의

AnyLogic 9 **웹 에디터의 UI 명칭은 데스크톱 8.9와 다를 수 있습니다.** 아래 절차는 *무엇을 달성해야 하는지*를 기준으로 썼습니다. 메뉴 이름이 다르면 같은 역할을 하는 항목을 찾으시고, **찾지 못한 항목은 기록지에 적어 두십시오** — 그 자체가 "교육에 쓸 만한가"의 중요한 판단 자료입니다.

## C1 · 웹 에디터로 5블록 모델을 만들 수 있는가

**판정하려는 것:** 실습3(M3 채널 폭주)을 브라우저에서 재현할 수 있는가.

### 단계

1. Cloud 로그인 → **My models** 화면
2. **New model** 클릭 → 이름 `CloudTest_M3` 입력 → **Create**
3. 웹 에디터가 열립니다. **여기서부터 스톱워치 시작** (소요 시간 자체가 판정 자료입니다)
4. 팔레트에서 **Process Modeling Library**를 찾아 아래 5개를 캔버스로 드래그하고 순서대로 연결합니다

   ```
   Source → Queue → Service → Sink
                       ↑
                  ResourcePool
   ```

   > 블록을 가까이 놓으면 연결선이 자동으로 나타납니다. 안 되면 포트끼리 직접 끌어 연결하십시오.

5. 각 블록 속성을 아래로 설정합니다

   | 블록 | 속성 | 값 | 비고 |
   |---|---|---|---|
   | Source | Arrivals defined by | Rate | |
   | Source | Arrival rate | **0.5 per minute** | 이용률 약 87.5% — 안정적이지만 대기줄이 생기는 수준 |
   | Service | Delay time | `triangular(4, 6, 11)` **minutes** | 본 과정의 창구 처리시간(평균 7분) |
   | Service | Resource pool | ResourcePool 지정 | |
   | ResourcePool | Capacity | **4** | 창구 4개 |

   > ⚠ **각 블록의 시간 단위 드롭다운이 `minutes`인지 반드시 확인하십시오.** 이 값이 어긋나면 이후 측정이 전부 무의미해집니다.

6. 모델 시간을 설정합니다 — 실험 속성의 **Model time** 영역에서
   - **Stop:** `Stop model at specified time`
   - **Stop time:** **10080** (= 7일 × 1,440분)
   - **Model time unit:** `minutes`

7. 저장(웹 에디터는 자동 저장) → **스톱워치 정지**

### 기록할 것

```
C1 소요 시간:          ______분
5블록 배치·연결:       [ ] 성공  [ ] 실패 — 막힌 지점: ______________________
속성 설정:             [ ] 성공  [ ] 실패 — 막힌 지점: ______________________
데스크톱과 다른 UI:    ______________________________________________
팔레트에서 못 찾은 것: ______________________________________________
```

### 판정

| 결과 | 의미 |
|---|---|
| **15분 이내 완성** | ✅ 실습3(42분 배정)을 브라우저로 진행 가능. 초보자는 강사의 2~3배가 걸리므로 15분이 상한선입니다 |
| 15~25분 | ⚠ 가능하나 실습 범위 축소 필요 |
| 25분 초과 또는 실패 | ❌ **데스크톱 유지.** 여기서 중단하고 C2~C4는 하지 않아도 됩니다 |

## C2 · 7일치 모델이 1분 안에 도는가

**판정하려는 것:** 무료 계정의 단일 실행 1분 제한 안에 본 과정의 모델이 들어오는가.

> C1에서 만든 `CloudTest_M3`를 **그대로** 씁니다.

### 단계

1. **애니메이션을 끕니다.** 실행 모드를 "가상 시간(최대 속도)"로 설정하십시오. 애니메이션이 켜져 있으면 측정이 무의미합니다
2. 실험 대시보드에서 **Run** 클릭 — **동시에 스톱워치 시작**
3. 실행이 끝나거나 중단될 때까지 기다립니다
4. **스톱워치 정지**

### 기록할 것

```
경과 시간(벽시계):     ______초
완주 여부:             [ ] 정상 완료  [ ] 제한으로 중단  [ ] 오류
중단됐다면 —
  중단 시점 모델시간:  ______분   (전체 10,080분 중)
  화면에 뜬 메시지:    ______________________________________________
  중단 방식:           [ ] 실행 정지  [ ] 경고만 뜨고 계속  [ ] 조용히 종료
처리된 개체 수:        ______개    (Sink의 count)
```

> ⚠ **"조용히 종료"가 가장 위험합니다.** 수강생이 "다 돌았다"고 믿고 잘린 결과를 해석하게 됩니다. 반드시 구분해 기록하십시오.

### 판정

| 결과 | 의미 |
|---|---|
| **30초 이내 완주** | ✅ 여유 충분. 실습3~4를 Cloud로 진행 가능 |
| 30~60초 완주 | ⚠ 아슬아슬. 실습에서는 모델 시간 지평을 **3일(4,320분)로 축소** 권장 |
| **1분 제한으로 중단** | ❌ 무료 계정으로는 불가. 유료 구독을 검토하거나 데스크톱 유지 |

## C4 · 모델시간 5시간 제한이 Cloud에도 있는가

**판정하려는 것:** PLE 데스크톱의 "1회 실행당 모델시간 5시간" 제한이 Cloud에도 적용되는가.

### 🎯 대부분의 경우 C2가 이미 답을 줍니다

**C2에서 10,080분(=7일=168시간)이 완주됐다면, 5시간(=300분) 제한은 존재하지 않는 것입니다.** 168시간 ≫ 5시간이므로 추가 테스트가 필요 없습니다.

→ 이 경우 [07 · T1~T4 검증](07-ple-verification.md)의 **트랙 A/B 분기 고민 자체가 사라집니다.** C4 항목에 "C2로 확인됨"이라고 적고 C3으로 넘어가십시오.

### C2가 중단된 경우에만 수행

중단 시점의 모델 시간을 보고 원인을 구분합니다.

| C2 중단 시점 모델시간 | 원인 | 조치 |
|---|---|---|
| **정확히 300분 근처** | **모델시간 5시간 제한이 Cloud에도 적용됨** | [07 트랙 B](07-ple-verification.md#4-트랙-결정-규칙) 또는 데스크톱 유지 |
| 300분과 무관한 값 | **벽시계 1분 제한**에 걸린 것 (모델시간 제한 아님) | C2 판정을 따름 |

확인 사격이 필요하면 — Stop time을 **290분**(5시간 미만)으로 낮춰 재실행하십시오.

```
290분 실행:  [ ] 완주  [ ] 중단
→ 완주했고 10,080분은 300분 근처에서 멈췄다면 → 모델시간 5시간 제한 확정
```

## C3 · 20복제 멀티런이 5분 안에 도는가 — **M5의 생사**

**판정하려는 것:** 실습5(정책 비교)의 시나리오당 20복제가 무료 한도 안에 들어오는가.

> 이 테스트가 실패하면 **실습5를 재설계해야 합니다.** [03 · M5](03-running-case.md#m5--정책-비교--실습5)에 이미 축소 대비책(복제 10회 → 시나리오 4개)이 적혀 있습니다.

### 단계

1. `CloudTest_M3`에서 **멀티런 계열 실험**을 새로 만듭니다 (Monte Carlo 또는 Parameter Variation)
2. 복제 횟수를 **20**으로 설정
3. Stop time은 C2에서 완주가 확인된 값을 씁니다 — 완주 못 했으면 **3일(4,320분)** 로 낮춰 진행
4. 애니메이션 **끔** 확인
5. **Run** — 동시에 스톱워치 시작
6. 종료 또는 중단 시 **스톱워치 정지**

### 기록할 것

```
Stop time 사용값:      ______분
경과 시간(벽시계):     ______분 ______초
완주 여부:             [ ] 20복제 전부 완료  [ ] 중단
중단됐다면 완료된 복제: ______ / 20
화면 메시지:           ______________________________________________
```

### 판정

| 결과 | 의미 |
|---|---|
| **2분 이내 완주** | ✅ 6시나리오 × 20복제를 실습5의 25분 슬롯에 넣을 수 있음 |
| 2~5분 완주 | ⚠ 6시나리오를 연달아 돌리면 슬롯 초과. **복제 10회** 또는 **시나리오 4개**로 축소 |
| **5분 제한으로 중단** | ❌ 무료 계정으로 M5 불가. 데스크톱 유지 또는 유료 구독 |

> 📌 실습5는 **6개 시나리오를 각각** 돌립니다. C3 소요 시간 × 6이 25분 슬롯에 들어오는지로 최종 판단하십시오. 예: 1회 90초 × 6 = 9분 → 기록·토론 시간까지 포함해 여유 있음.

## 종합 판정표

네 결과를 모아 최종 결정을 내립니다.

| C1 | C2 | C3 | 결론 |
|:---:|:---:|:---:|---|
| ✅ | ✅ | ✅ | **Cloud를 주 실습 환경으로 전환 검토.** 단 Technology Preview 리스크는 남음 — 아래 참조 |
| ✅ | ✅ | ⚠/❌ | **하이브리드:** 실습1~4는 Cloud, **실습5만 데스크톱**. 운영이 복잡해지므로 권장하지 않음 |
| ✅ | ❌ | — | 무료 계정으로는 불가. **유료 구독 견적**을 받아 볼 가치는 있음 |
| ❌ | — | — | **현행 유지** — 데스크톱 PLE + 전산실 D-7 일괄 설치 |

### 전부 통과해도 남는 것 — 전환 전 확인 사항

1. **Technology Preview 상태.** 16명이 동시에 쓰는 유상 교육을 미리보기 버전에 올리는 위험을 발주 학과와 합의해야 합니다
2. **학교 네트워크에서 `cloud.anylogic.com` 접근 가능 여부.** 설치 문제는 사라져도 **네트워크 접근은 여전히 필요**합니다. [05 · 2.2](05-operations-and-license.md#22-그-밖의-전산실-확인-사항)의 방화벽 확인 항목이 그대로 유효합니다
3. **수강생 계정 16개.** 각자 Cloud 가입이 필요합니다. 사전 설문(D-3)에 가입 안내를 추가해야 합니다
4. **문서 재작성 범위.** UI가 다르면 [04 워크북](04-labs-and-materials.md)의 클릭 경로, [08 런북](08-instructor-runbook.md)의 발화, 스크린캐스트 5편을 전부 다시 만들어야 합니다. **이 재작업 비용이 설치 문제 해소 이익보다 큰지** 따져 보십시오
5. **`Mx_start`/`Mx_done` 배포 방식.** 파일 배포 대신 **모델 공유**로 바뀝니다. Cloud에서 각 학생에게 모델 복제본을 주는 방법을 확인해야 합니다

> **필자 권고:** C1~C3가 전부 통과해도 **이번 회차는 데스크톱으로 진행하고, Cloud는 다음 회차 전환 후보로 두는 것**을 권합니다. 4번(문서 재작성)과 1번(미리보기 리스크)이 이번 일정 안에 흡수되기 어렵습니다. 대신 이번 회차에서 Cloud를 **결과 공유 경로**(완성 모델을 Cloud에 퍼블리시해 수강생이 수업 후에도 열어 보게 함)로 쓰면 재작업 없이 이점만 취할 수 있습니다.
