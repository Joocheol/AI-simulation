## 2. 교육 배경 및 필요성

### 2.1 왜 지금 시뮬레이션인가

2023년의 두 사건은 위기 대응 계획의 전제를 바꿔 놓았습니다.

- **SVB (2023-03-09)** — 하루 만에 **$42B 규모의 인출 시도**가 발생했고, 마감 시점 현금잔액은 **-$958M** 이었습니다. 앱·디지털 채널에는 물리적 대기줄이라는 완충장치가 없습니다.
- **새마을금고 (2023-07)** — 부동산 PF 부실 우려가 확산되며 한 달간 예·적금 중도해지가 **41만 7,367건** 발생했습니다(전년 동기 20만 3,267건의 2배). 대면 창구 중심이었기에 지점 처리용량이 병목으로 작동했습니다.

같은 "뱅크런"이지만 **전개 속도가 전혀 달랐고, 그 차이를 만든 것은 채널 구성과 처리용량**이었습니다.

### 2.2 엑셀의 평균이 답하지 못하는 질문

실무에서 위기 대응 용량은 흔히 평균으로 계산됩니다. "하루 평균 인출 200건, 창구 4개, 건당 7분이니 감당 가능."

그러나 이 계산은 다음을 말해주지 못합니다.

| 실무 질문 | 평균 계산의 한계 |
|---|---|
| 인출이 2배가 되면 대기시간은 2배인가? | **아니오.** 처리용량에 근접할수록 대기시간은 비선형으로 폭발합니다 |
| 유동성이 바닥날 확률은 몇 %인가? | 평균값 하나로는 **확률을 말할 수 없습니다** |
| 최악의 경우 얼마나 나쁜가? | 평균은 정의상 **꼬리(tail)를 보여주지 않습니다** |
| 창구 2명을 늘리면 얼마나 좋아지나? | 대기행렬의 비선형성 때문에 **직관이 자주 틀립니다** |

시뮬레이션은 이 네 질문에 **확률과 분포로** 답합니다. 이 과정의 목적은 수강생이 그 답을 **직접 만들어 보고, 읽고, 의사결정에 쓰는 경험**을 하는 것입니다.

## 3. 학습 목표 및 성취 수준

### 3.1 성취 수준 사다리

시뮬레이션 역량은 단계적입니다. 5시간이 어디까지 데려다줄 수 있는지를 먼저 정직하게 규정합니다.

| 단계 | 정의 | **5시간 후 도달도** |
|---|---|---|
| **L1 해석자 (Reader)** | 시뮬레이션 결과를 읽고 의미를 판단하며, 그 한계를 지적할 수 있다 | **100%** |
| **L2 사용자 (Operator)** | 주어진 모델의 파라미터를 바꿔 실험을 돌리고 시나리오를 비교할 수 있다 | **80%** |
| **L3 제작자 (Builder)** | 백지에서 모델을 설계·구현·검증할 수 있다 | **20% (맛보기)** |

> **이 과정은 L1을 완성하고 L2를 확보하며 L3를 맛보게 하는 과정입니다.**

### 3.2 학습 목표 (측정 가능)

각 목표는 특정 실습 및 체크포인트와 1:1로 연결됩니다. 추적표는 [06 · 평가와 후속](06-assessment-and-followup.md#3-학습목표-추적표)에 있습니다.

| # | 학습 목표 | 수준 | 달성 실습 |
|---|---|---|---|
| **O1** | 평균 기반 계산이 실패하는 상황을 설명하고, 시뮬레이션이 필요한 문제와 아닌 문제를 구분한다 | L1 | 오프닝 퀴즈 |
| **O2** | 확률분포·난수·시드·모델시간 개념을 사용해 모델 입력을 설정한다 | L2 | 실습1 (M1) |
| **O3** | 몬테카를로 결과의 히스토그램에서 **꼬리위험과 신뢰구간**을 읽고, 1회 실행 결과를 신뢰하면 안 되는 이유를 설명한다 | L1 | 실습2 (M2) |
| **O4** | 입력 변수를 스윕해 **시스템이 무너지는 임계점**을 찾는다 | L2 | PV 데모 |
| **O5** | Process Modeling Library로 창구 처리 프로세스를 조립하고, 도착률 변화가 대기행렬에 미치는 영향을 관찰한다 | L2/L3 | 실습3 (M3) |
| **O6** | Statechart로 예금자 행동을 표현하고, 확산 계수를 조정해 위기 전개 속도를 바꾼다 | L2/L3 | 실습4 (M4) |
| **O7** | 정책 대안별 시나리오 실험 결과를 비교표로 정리하고 **정책 권고를 도출한다** | L1/L2 | 실습5 (M5) |
| **O8** | 본인 업무 문제를 시뮬레이션 문제로 1페이지 정의한다 | L1 | 적용 워크숍 |

### 3.3 도달 가능 — 교육 성과로 명시해도 되는 것

- 평균 기반 계산의 한계와 확률적 접근의 필요성을 **업무 언어로 설명**한다
- 난수·시드·복제·수렴·신뢰구간·꼬리위험 용어를 **정확히 사용**한다
- 기존 모델을 열어 파라미터를 바꿔 실행하고 **차트를 해석**한다
- 템플릿 위에서 **5블록 규모의 프로세스 흐름을 재현·수정**한다
- **시나리오 비교 실험을 설계하고 결과표로부터 정책 권고를 도출**한다
- 자기 업무를 시뮬레이션 문제로 **프레이밍**한다 (1페이지 캔버스)
- 내부 개발팀·외주에 **요구사항을 말할 수 있는 발주 역량**을 갖춘다

> 마지막 항목이 실무적으로 가장 가치가 높습니다. 많은 조직에서 시뮬레이션 프로젝트가 실패하는 이유는 모델링 기술의 부재가 아니라 **"무엇을 물어야 하는지 모르는 것"** 입니다.

### 3.4 범위 밖 — 명시적 비목표

기대 관리를 위해 **아래는 이 과정의 목표가 아님을 문서와 오리엔테이션 양쪽에서 선언**합니다.

- ❌ 백지에서 독자적 모델 설계·구현
- ❌ Java 코드 작성·디버깅, 커스텀 에이전트 로직
- ❌ 실데이터 연결(DB/Excel import)과 **분포 적합(distribution fitting)**
- ❌ **검증(validation)·보정(calibration) 수행** — 개념 언급까지만
- ❌ 최적화(OptQuest) 실전 활용 — PLE 제한(변수 7개·500 iteration)도 겹칩니다
- ❌ **모델 결과를 규제 보고나 실제 의사결정에 직접 사용**

> 마지막 항목은 문서뿐 아니라 **마무리 세션에서 구두로도 반드시 고지**합니다. 교육용 미검증 모델이라는 고지 없이 수강생이 결과를 사내에 가져가면 심각한 문제가 됩니다.

### 3.5 참고 — 왜 "혼자 모델을 만들 수 있다"를 내걸지 않는가

AnyLogic 공식 기초 과정은 통상 **3일(20~24시간)** 이며, 그것조차 백지 창작 역량을 보장하지 않습니다. 이 과정은 그 **1/5 분량**이고 대상은 코딩 경험이 없는 완전 초심자입니다. 백지 창작에는 최소 **20~40시간 학습 + 실제 프로젝트 1건 완주**가 필요합니다.

"혼자 모델을 만들 수 있다"를 목표로 내거는 것은 위탁 기업의 기대를 과도하게 부풀려 **종료 후 만족도 평가에서 반드시 역풍을 맞습니다.**

## 4. 수강 전제조건 및 사전 준비

### 4.1 전제조건

| 항목 | 요구 수준 |
|---|---|
| 프로그래밍 | **불필요.** 코드 노출은 엑셀 수식 수준의 표현식으로 한정 |
| 엑셀 | 함수·차트를 다뤄본 수준 (설명의 비유로 적극 활용) |
| 통계 | **불필요.** 평균·표준편차 개념만 있으면 충분 |
| 업무 배경 | 창구·채널·리스크 중 하나의 업무 맥락이 있으면 몰입도가 높아짐 |

### 4.2 사전 준비 — 설치 과제가 없습니다

학교 전산실을 사용하므로 **수강생 개인의 설치 부담이 없습니다.** AnyLogic PLE는 D-7에 전산실 PC에 일괄 설치되고, 전원이 동일 환경에서 시작합니다. 사내 교육에서 가장 흔한 실패 원인(당일 설치 지연) 자체가 제거됩니다.

대신 D-3에 **짧은 사전 설문**만 발송합니다.

1. 소속 업무 영역 (창구 · 채널 · 리스크 · 기획 중)
2. 업무에서 **"값이 매번 달라져서 곤란한 것"** 1가지
3. 엑셀 사용 수준 (자가평가)

이 응답은 **오프닝 사례와 적용 워크숍을 수강생 업무에 맞춰 조정하는 재료**가 됩니다. 상세는 [05 · 2.4](05-operations-and-license.md#24-수강생-사전과제--설치에서-설문으로)를 참조하십시오.

## 5. 소프트웨어 라이선스 고지 (요약)

> **AnyLogic PLE 라이선스는 "teaching or self-education purposes only" 를 허용합니다.**
> 대학이 주관하는 이 과정은 정확히 그 허용 범위에 해당하므로, **라이선스 해석 쟁점이 발생하지 않습니다.**
>
> 다만 두 가지는 별도로 주의해야 합니다.
>
> 1. **연구(research) 목적 사용은 금지**됩니다. 조교(TA)나 연구실이 교육용 PLE를 연구에 전용하지 않도록 사전 고지가 필요합니다.
> 2. **수강생이 소속 회사 업무에 적용하려면 별도 라이선스가 필요합니다.** 학교에서 배웠다는 사실과 무관합니다.
>
> 전체 정책과 경로 비교는 [05 · 라이선스 정책](05-operations-and-license.md#3-소프트웨어-라이선스-정책)을 참조하십시오.
