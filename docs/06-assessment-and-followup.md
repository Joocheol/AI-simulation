# 06 · 평가와 후속

## 1. 체크포인트 정의

체크포인트는 평가 도구이자 **복구 지점**입니다. 각 CP마다 워크북에 **"이 화면이 보이면 성공"** 스크린샷을 배치하고, 도달하지 못한 수강생은 완성 파일을 열어 합류합니다.

| CP | 시점 | 완성 판정 기준 | 미달 시 |
|---|---|---|---|
| **CP0** | 각 일차 도입 | 지정 파일이 열려 있고 화면이 강사와 동일하다 | 조교 즉시 개입 · 예비기 |
| **CP1** | 1일차 00:50 | 파라미터 3개가 입력되어 있다 | 페어 파트너와 화면 공유 |
| **CP2** ★ | 1일차 01:10 | **실행 시 히스토그램에 막대가 그려진다** | `M1_done` 배포 |
| **CP3** | 1일차 01:55 | 복제 1,000회 실행이 완료된다 | `M2_done` 배포 |
| **CP4** ★ | 1일차 02:05 | **P(유동성 부족) 값을 워크시트에 기록했다** | 강사가 값 공유 |
| **CP5** | 2일차 00:40 | `Source→Queue→Service→Sink` + ResourcePool 5블록이 연결되어 있다 | `M3_done` 배포 |
| **CP6** ★ | 2일차 00:55 | **위기 도착률로 바꿨을 때 대기열 발산을 확인했다** | `M3_done` 배포 |
| **CP7** | 2일차 01:42 | Statechart 3상태 3전이가 완성되고 확산 곡선이 그려진다 | `M4_done` 배포 |
| **CP8** ★ | 2일차 02:10 | **비교표를 채우고 권고안 1줄을 적었다** | 조별 작성 허용 |

★ = 수료 필수 체크포인트

> **CP4·CP6·CP8은 소프트웨어 조작이 아니라 해석 결과를 판정합니다.** 이 과정의 진짜 목표(L1 해석자)가 여기에 있습니다.

---

## 2. 수료 기준

| 기준 | 요건 |
|---|---|
| 출석 | 2회차 모두 참석 (5시간 중 4시간 이상) |
| 실습 | **CP2 · CP4 · CP6 · CP8 도달** (필수 4개) |
| 산출물 | **1페이지 적용 캔버스 제출** |

필수 CP를 4개로 좁힌 이유: CP1·CP3·CP5·CP7은 **조작 단계**이므로 완성 파일로 대체해도 학습이 이어지지만, **CP2(첫 실행 성공)·CP4(확률 해석)·CP6(비선형성 확인)·CP8(정책 권고)** 은 이 과정의 학습목표 그 자체이기 때문입니다.

---

## 3. 학습목표 추적표

| 목표 | 내용 | 수준 | 달성 활동 | 확인 |
|---|---|:---:|---|---|
| **O1** | 평균 계산의 실패 상황을 설명하고 시뮬레이션 적용 대상을 구분 | L1 | 오프닝 퀴즈 · 실습3 | 사후 자가진단 Q1–Q2 |
| **O2** | 분포·난수·시드·모델시간으로 입력을 설정 | L2 | 실습1 (M1) | **CP1, CP2** |
| **O3** | 히스토그램에서 꼬리위험·신뢰구간을 읽고, 1회 실행을 신뢰하면 안 되는 이유 설명 | L1 | 실습2 (M2) | **CP4** |
| **O4** | 입력을 스윕해 시스템이 무너지는 임계점을 찾음 | L2 | PV 데모 | 사후 자가진단 Q5 |
| **O5** | PML로 창구 프로세스를 조립하고 도착률 영향을 관찰 | L2/L3 | 실습3 (M3) | CP5, **CP6** |
| **O6** | Statechart로 행동을 표현하고 확산 계수를 조정 | L2/L3 | 실습4 (M4) | CP7 |
| **O7** | 정책별 실험 결과를 비교표로 정리하고 권고 도출 | L1/L2 | 실습5 (M5) | **CP8** |
| **O8** | 본인 업무를 시뮬레이션 문제로 1페이지 정의 | L1 | 적용 워크숍 | 캔버스 루브릭 |

> **8개 목표 전부가 특정 활동과 확인 수단에 연결되어 있습니다.** 빈칸이 생기면 그 목표는 측정 불가능하므로 목표에서 내려야 합니다.

## 4. 효과 측정

### 4.1 사전/사후 자가진단 (동일 10문항, 5점 척도)

위탁 기업이 원하는 정량 지표입니다. **같은 문항을 D-3과 종료 직후에 실시**해 변화량을 봅니다.

| # | 문항 |
|---|---|
| Q1 | 평균값만으로 위기 대응 용량을 계산하면 안 되는 이유를 설명할 수 있다 |
| Q2 | 어떤 업무 문제에 시뮬레이션이 적합한지 판단할 수 있다 |
| Q3 | 확률분포를 상황에 맞게 고를 수 있다 |
| Q4 | 시뮬레이션을 한 번만 돌린 결과를 신뢰하면 안 되는 이유를 안다 |
| Q5 | 결과 히스토그램에서 꼬리위험을 읽을 수 있다 |
| Q6 | 대기행렬에서 도착률과 대기시간이 비례하지 않는 이유를 안다 |
| Q7 | AnyLogic에서 모델을 열고 파라미터를 바꿔 실행할 수 있다 |
| Q8 | 간단한 프로세스 흐름(5블록)을 만들 수 있다 |
| Q9 | 시나리오를 비교해 정책을 권고할 수 있다 |
| Q10 | 내 업무 문제를 시뮬레이션 요구사항으로 설명할 수 있다 |

### 4.2 실습 완주율

CP0~CP8 도달자 수를 기록합니다. **CP별 이탈률이 다음 회차 커리큘럼 개선의 1차 데이터**입니다.

### 4.3 캔버스 루브릭 (20점)

| 항목 | 4점 | 2점 | 0점 |
|---|---|---|---|
| **문제 정의** | 의사결정 시점과 대안이 명확 | 문제는 있으나 모호 | 업무 설명에 그침 |
| **불확실성 요소** | 값이 변동하는 요소를 3개 이상 구체적으로 식별 | 1~2개 | 없음 |
| **성과지표(KPI)** | 측정 가능하고 의사결정과 연결됨 | 측정 가능하나 연결 약함 | 추상적 |
| **의사결정 변수** | 조직이 실제로 바꿀 수 있는 것 | 일부 통제 불가 항목 포함 | 전부 통제 불가 |
| **기대 효과** | 정량 추정 시도 | 정성 서술 | 없음 |

### 4.4 만족도 설문

- 내용 난이도 (너무 쉬움 1 ~ 너무 어려움 5) — **3에 가까울수록 좋음**
- 실습 분량 적정성
- 업무 관련성
- 강사·조교 지원 충분성
- **"동료에게 추천하겠는가"** (NPS)
- 자유 서술: 가장 유익했던 것 / 가장 어려웠던 것

### 4.5 사후 추적 (선택, 3개월)

- 교육 후 시뮬레이션을 업무에 적용해 본 적이 있는가
- 적용했다면 어떤 문제에
- 적용하지 못했다면 가장 큰 장애는 무엇인가 (도구 / 데이터 / 시간 / 라이선스)

> 학교 주관 교육이라 라이선스·설치 장벽은 **교육 중에는** 없지만, 수강생이 **회사로 돌아가면 다시 생깁니다**(사내 PLE 사용 불가, 사내 PC 설치 제약). 이 문항의 답이 "라이선스"와 "환경"으로 몰린다면 교육의 효과가 아니라 **실행 조건의 문제**임을 구분해 읽으십시오 → [05 · 3.4](05-operations-and-license.md#34-수강생의-사내-전용-경로)

## 5. 강사 회고 체크리스트

교육 직후 강사·조교가 15분 내에 기록합니다.

- Go/No-Go 분기점 중 발동된 것과 그 시점
- 각 CP 도달률과 지연 원인
- 예상 밖 질문 · 막힌 지점 (워크북 개정 후보)
- PLE 한도 관련 실제 발생 문제
- 다음 회차에 바꿀 것 3가지

### 6.3 Level 2 과정 제안 (별도 기획)

본 과정이 다루지 않은 것들이 Level 2의 내용이 됩니다 → [01 · 3.4 범위 밖](01-course-overview.md#34-범위-밖--명시적-비목표)

- 실데이터 연결 (Excel/DB import)과 **분포 적합(distribution fitting)**
- **검증(validation)·보정(calibration)** 실습
- 최적화(OptQuest) 실전 활용
- 백지에서 모델 설계 — **수강생 각자의 업무 문제로**
- 결과 공유 (AnyLogic Cloud 퍼블리시, 대시보드 구성)

> Level 2는 **본 과정에서 나온 캔버스를 입력으로 삼을 때 가장 효과적**입니다. 두 과정 사이에 PoC 기간을 두는 것을 권장합니다.
