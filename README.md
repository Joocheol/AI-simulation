# Mesa로 배우는 시뮬레이션 — pi 구하기에서 창발까지

가장 단순한 몬테카를로(pi 추정)에서 출발해, 에이전트 기반 모형(ABM)이
왜 필요한지까지 **한 줄씩 규칙을 추가해 가며** 따라가는 5단계 튜토리얼입니다.
모든 코드는 실행되고, 모든 주장은 이론값이나 테스트로 검증되어 있습니다.

## 왜 pi부터 시작하는가

시뮬레이션을 처음 배울 때 가장 흔한 실패는, **새 도구(Mesa)와 새 문제(ABM)를
동시에** 배우려다 둘 다 놓치는 것입니다.

그래서 이 튜토리얼은 이미 답을 아는 문제에서 출발합니다.
pi는 참값을 알고, 오차의 이론식도 알고, 결과가 틀리면 바로 알아챌 수 있습니다.
**정답지가 있는 문제 위에서 도구를 익히고, 정답지가 없는 문제로 옮겨 갑니다.**

| 단계 | 문제 | 새로 추가되는 것 | 정답지 |
|:---|:---|:---|:---|
| 1 | pi 추정 (순수 파이썬) | 난수·반복·집계 | pi, 오차 = 1/√N |
| 2 | pi 추정 (Mesa) | Agent / Model / DataCollector | 위와 동일 |
| 3 | 랜덤워크 | **공간**(격자), 이웃 | MSD = 1.5·t |
| 4 | 부의 교환 | **상호작용** | 기하분포, 지니 0.667 |
| 5 | 셸링 분리 모형 | **창발**, 파라미터 스윕 | **없음** ← ABM이 필요한 지점 |
| 6 | SVB 뱅크런 | **실제 사건**, 다중균형, 반사실 실험 | 없음 (실제 수치와 대조) |

## 설치와 실행

```bash
pip install -r requirements.txt      # mesa 3.x (3.3에서 검증)

python3 steps/step01_pi_plain.py     # 1단계부터 순서대로
python3 steps/step02_pi_mesa.py
python3 steps/step03_random_walk.py
python3 steps/step04_wealth.py       # 약 45초 (반복 실행 실험 포함)
python3 steps/step05_schelling.py    # 약 13초
python3 steps/step06_bankrun.py      # 약 26초

python3 tests/test_steps.py          # 25개 검증 테스트 (pytest 불필요)
```

각 파일의 맨 위 독스트링에 그 단계의 이론적 배경이, 코드 안에는 줄 단위
주석이 들어 있습니다. 파일 하나가 강의 한 꼭지에 대응합니다.

## 1단계 — 순수 파이썬 몬테카를로

[`steps/step01_pi_plain.py`](steps/step01_pi_plain.py)

한 변이 2인 정사각형에 점을 뿌리고, 반지름 1인 원 안에 들어간 비율을 셉니다.
넓이 비가 pi/4이므로 `pi ≈ 4 × (안에 들어간 수) / (전체 수)`.
적분을 푸는 대신 **해 보고 세어서** 답을 얻습니다.

**Mesa를 쓰지 않는 것이 핵심입니다.** 시뮬레이션에 특별한 라이브러리가
필요하지 않다는 것, 그리고 모든 시뮬레이션이 다음 네 부품으로 되어 있다는 것을
먼저 봅니다.

```
1) 상태(state)       inside, total
2) 규칙(rule)        점 하나를 뽑고 x²+y² ≤ 1 인지 판정
3) 반복(iteration)   N번 되풀이
4) 집계(aggregation) 4 × inside / total
```

이 네 가지는 5단계까지 그대로 반복됩니다. 2단계에서 Mesa가 하는 일은
여기에 **이름표를 붙여 주는 것**뿐입니다.

실행하면 확인하게 되는 것:

```
         N        추정 pi        실제 오차        이론 SE
       100     3.200000     0.058407     0.164218
     1,000     3.180000     0.038407     0.051930
    10,000     3.139200     0.002393     0.016422
   100,000     3.140280     0.001313     0.005193
10,000,000     3.142174     0.000581     0.000519
```

- **오차는 1/√N로 줄어든다.** 오차를 1/10로 만들려면 표본을 100배 늘려야 합니다.
  몬테카를로가 느린 이유이고, 이 느림은 "수렴하지 않음"과는 전혀 다릅니다.
- **결과는 숫자 하나가 아니라 분포다.** seed만 바꿔 30번 돌리면
  3.1156 ~ 3.1584로 흩어집니다. 한 번 돌린 값으로 결론 내면 안 되는 이유입니다.
- **seed는 재현성을 결정한다.** 논문·보고서에 반드시 기록해야 할 값입니다.

## 2단계 — 같은 계산을 Mesa로

[`steps/step02_pi_mesa.py`](steps/step02_pi_mesa.py)

답은 1단계와 같습니다. 목적은 **이미 아는 문제 위에서 Mesa의 뼈대를 익히는 것**입니다.

| 1단계의 코드 | Mesa의 부품 |
|:---|:---|
| 점을 던지는 주체 (암묵적) | `Agent` — 다트를 던지는 사람 |
| `inside`, `total` 변수 | Agent / Model 속성 |
| 점 뽑기 + 판정 | `Agent.step()` — 한 에이전트의 1회 행동 |
| `for _ in range(N)` | `Model.step()` — 전체의 1회 시간 전진 |
| `4 * inside / total` | `DataCollector` — 매 스텝 자동 기록 |
| `random.Random(seed)` | `Model(seed=...)` — 모형 전체가 공유 |

솔직하게 말하면 **pi 추정에 ABM은 명백한 과잉입니다.** 에이전트들이 서로를
쳐다보지 않기 때문에 1000명이 1번씩 던지든 1명이 1000번 던지든 결과는 같습니다.
Mesa가 필요해지는 것은 **에이전트가 서로에게 반응하기 시작할 때**이고,
그 순간 손으로 푸는 수식이 막힙니다. 4·5단계가 그 예입니다.

여기서 "수렴"의 정확한 의미도 짚습니다. 값이 참값에 *도달*하는 것이 아니라,
**참값 주변의 구름이 조여드는 것**입니다.

```
     스텝 구간        최솟값        최댓값          폭      이론 SE
         1-100     3.1067     3.1600     0.0533     0.0164
       101-200     3.1350     3.1485     0.0135     0.0095
       301-400     3.1322     3.1380     0.0058     0.0062
       401-500     3.1335     3.1379     0.0043     0.0055
```

최종 오차가 이론 SE의 1.55배로 나오는데, **이것이 정상입니다.**
매번 0에 가깝게 나온다면 오히려 난수나 집계 코드를 의심해야 합니다.

## 3단계 — 공간을 얹는다: 랜덤워크

[`steps/step03_random_walk.py`](steps/step03_random_walk.py)

2단계까지 에이전트는 '어디에도' 없었습니다. 이제 격자 위에 세웁니다.
공간이 생기면 **이웃**이라는 개념이 따라오고, 이웃이 있어야 다음 단계의
상호작용이 가능해집니다. 아직 서로 영향은 주지 않습니다.

**핵심 주장: 개별 궤적은 완전히 예측 불가능한데, 집단의 통계량은 정확히 예측된다.**

무어 이웃 8칸 중 하나를 균등하게 고르면 `E[dx²] = 6/8 = 0.75`이므로
t스텝 후 평균제곱변위는 **MSD(t) = 1.5·t**. 코드가 이것을 재현하는지 봅니다.

```
     t      MSD(측정)     1.5t(이론)       비율     RMS 거리
     5        7.402        7.500    0.987      2.721
    25       36.186       37.500    0.965      6.015
   100      150.624      150.000    1.004     12.273
```

같은 실행에서 개인별 제곱변위는 최소 1, 중앙값 117, 최대 968으로 제각각입니다.
**한 명의 미래는 예측할 수 없지만 500명의 평균은 1.5t로 예측됩니다.**
"확률적 모형은 여러 번 돌려 평균으로 말한다"는 원칙의 근거가 여기 있습니다.

또 거리가 √t에 비례한다는 것 — 시간이 4배가 되어도 거리는 2배밖에 늘지 않습니다.
1단계의 1/√N과 같은 뿌리(중심극한정리)입니다.

## 4단계 — 상호작용을 얹는다: 불평등의 창발

[`steps/step04_wealth.py`](steps/step04_wealth.py)

규칙 한 줄을 더합니다. **"같은 칸에 있는 누군가에게 내 돈 1을 준다."**

**핵심 주장: 완벽하게 대칭적이고 공정한 규칙에서도 극심한 불평등이 나타난다.**

모두 같은 돈으로 시작하고, 누구도 더 유능하지 않고, 이자도 상속도 착취도 없고,
주는 사람과 받는 사람은 매번 무작위입니다. 그런데:

```
    스텝       지니     최대 부     무일푼 수       총액
     1       0.4762        5         65      200
    10       0.6539        6        100      200
   100       0.6949       11        103      200
  1000       0.6486        8         99      200
```

지니계수가 0에서 출발해 **첫 스텝 만에 0.48**을 넘고 0.6대에서 진동합니다.
계속 나빠지는 것이 아니라 정상 상태에 도달해 머무는 것이고,
그 안에서 **누가 부자인지는 계속 바뀝니다**. 구조는 고정, 개인은 유동.

### 이 단계에서 가장 중요한 부분: 이론과 안 맞을 때

교과서에는 이 모형의 지니계수가 **0.5**라고 나옵니다. 그런데 측정값은 0.65입니다.
버그일까요?

아닙니다. 0.5는 **돈을 무한히 잘게 쪼갤 수 있을 때(연속 지수분포)**의 값입니다.
우리 모형은 1원 단위로 거래하므로 정상분포가 이산 **기하분포** `P(k) = (1/2)^(k+1)`이고,
그 지니계수는 **0.667**입니다. 실제로 분포 모양이 정확히 맞습니다.

```
   부 k        관측 비율     이론 (1/2)^(k+1)      관측/이론
     0       0.4875             0.5000       0.97
     1       0.2640             0.2500       1.06
     2       0.1255             0.1250       1.00
     3       0.0605             0.0625       0.97
```

그리고 초기 부를 늘리면 이산성이 약해져 교과서의 0.5로 내려갑니다.

```
    초기 부        측정 지니        기하분포 이론      연속 극한
       1       0.6688         0.6667     0.5000
       2       0.5855         0.6000     0.5000
      10       0.5284         0.5238     0.5000
```

남은 1~2%의 차이는 **유한 크기 효과**입니다 — 표본 지니의 편향과,
총액이 200으로 정확히 고정된 제약 때문입니다.
**이 정도 차이를 "버그"와 "유한 크기 효과"로 구분하는 것이 검증의 실제 내용입니다.**
억지로 맞추려 들면 안 됩니다.

> 총액이 항상 200으로 보존되는지도 매 스텝 확인합니다. 이런 **불변량 검사**를
> 코드에 박아 두면, 결과가 이상할 때 "모형이 그런 것"인지 "코드가 틀린 것"인지
> 빠르게 갈라낼 수 있습니다.

## 5단계 — 셸링 분리 모형: 정답지가 없는 곳

[`steps/step05_schelling.py`](steps/step05_schelling.py)

이제 손으로 풀 수 있는 해가 없는 문제입니다. 돌려 보는 것 외에 방법이 없습니다.
**ABM이 실제로 쓰이는 곳이 여기입니다.**

규칙은 하나뿐입니다. **"내 이웃 중 나와 같은 종류가 일정 비율에 못 미치면 이사 간다."**
그 비율이 관용도입니다. 0.3이면 *이웃의 70%가 나와 달라도 괜찮다*는,
현실의 어떤 기준으로 봐도 관용적인 사람입니다.

**핵심 주장: 아무도 분리를 원하지 않아도 분리가 일어난다.**

관용도 0.3짜리 주민만 모아 놓았는데, 7스텝 만에 전원이 만족하며 멈춘 상태의
분리 지표는 **0.797**입니다. 요구한 것은 0.3이었는데 도달한 곳은 0.80.
아무도 원한 적 없는 수준의 분리입니다.

원인은 연쇄 반응입니다. 한 사람이 이사하면 그 자리의 이웃 구성이 바뀌고,
그 때문에 불만족해진 사람이 또 이사합니다. 각자는 작은 기준을 채우려 했을 뿐인데
서로를 밀어내며 거시적 패턴을 만듭니다.

> **정책적 함의:** 관찰된 분리로부터 "사람들이 분리를 원한다"를 **추론할 수 없습니다.**

### 파라미터 스윕과 상전이

이론값이 없으니 다른 것으로 답해야 합니다. 관용도를 훑습니다.

```
     관용도        분리 지표       표준편차      멈춘 스텝      해결됨
   0.000        0.508      0.015        1.0      5/5
   0.125        0.524      0.023        2.0      5/5
   0.250        0.604      0.020        4.8      5/5
   0.375        0.783      0.027        9.6      5/5
   0.500        0.877      0.016       11.0      5/5
   0.750        0.991      0.003       58.8      5/5
   0.875        0.530      0.024      200.0      0/5
```

0.25 → 0.375 구간에서 지표가 0.60에서 0.78로 튀어오릅니다.
개인 기준의 작은 변화가 거시 결과의 큰 변화를 만드는 **상전이**입니다.
"관용도를 조금 올리면 분리도 조금 줄겠지"라는 선형적 직관이 통하지 않습니다.

### 이 튜토리얼 전체에서 가장 중요한 함정

마지막 줄을 보세요. 관용도 0.875에서 분리 지표가 **0.530으로 떨어집니다.**
"관용도가 아주 높으면 오히려 통합되는구나"라고 읽으면 **완전히 틀립니다.**

`해결됨` 열이 **0/5**입니다. 이 실행들은 끝까지 멈추지 못했습니다.
이웃 8명 중 7명 이상이 나와 같기를 요구하면 그런 자리는 거의 없습니다.
그래서 주민 대부분이 영원히 이사를 반복하고, 계속 무작위로 재배치되니
지표가 무작위 값인 0.5로 돌아간 것입니다.
**통합이 아니라 모형이 정상 상태에 도달하지 못한 상태입니다.**

지표 하나만 떼어 보지 말고, **그 숫자가 나온 상태가 무엇인지**
(수렴했는가? 몇 스텝에 멈췄는가? 여전히 움직이는가?) 반드시 함께 확인해야 합니다.
`unhappy`와 `steps_taken`을 같이 기록한 이유입니다.

마지막으로 같은 스윕을 `mesa.batch_run`으로 자동화합니다. 파라미터가
3~4개로 늘어나면 손으로 짠 이중 for문으로는 관리가 되지 않습니다.

## 6단계 — SVB 파산: 실제 사건에 적용해 보기

[`steps/step06_bankrun.py`](steps/step06_bankrun.py) ·
[숫자와 출처](docs/svb-sources.md)

1~5단계가 교과서 모형이었다면, 6단계는 2023년 3월에 실제로 일어난
실리콘밸리은행(SVB) 파산입니다. 먼저 **"재현"이라는 말을 나눠야** 합니다.

| 할 수 있는 것 | 할 수 없는 것 |
|:---|:---|
| 왜 멀쩡해 보이던 은행이 이틀 만에 무너지는가 | 어느 은행이 언제 무너질지 예측하는 것 |
| 왜 같은 손실을 안고도 어떤 은행은 버티는가 | 3월 9일의 420억 달러를 맞히는 것 |
| 어떤 개입이 효과가 있고 어떤 것이 없는가 | 한 스텝이 몇 시간인지 말하는 것 |

5단계 셸링 모형이 특정 도시의 인구 분포를 맞히지 못해도 "분리가 어떻게
생기는가"는 설명했던 것과 같습니다. **설명하지 예측하지 않습니다.**

### 이 사건의 핵심은 숫자 하나에 있습니다

SVB의 2022년 말 재무제표에서:

```
증권 미실현손실  152억(만기보유) + 25억(매도가능) = 177억 달러
자기자본                                          160억 달러
```

**미실현손실이 자기자본보다 큽니다.** 시가로 평가하면 자본이 이미 음수였는데,
만기까지 보유하면 손실을 실현하지 않으므로 장부상으로는 자본비율 +9.1%의
멀쩡한 은행이었습니다. 모형이 이 비율을 그대로 재현합니다.

```
항목                               모형        예금 대비         SVB 실제
장부 자기자본                      1.30B         9.1%          +9.1%
시가평가 자기자본                 -0.14B        -1.0%         -0.97%
무보험 예금 비율                                95.7%         85~94%
```

여기서 구조가 나옵니다. **아무도 빼지 않으면 살고, 빼기 시작하면 죽습니다.**
게다가 이 은행이 지급할 수 있는 최대 금액은 예금의 61.5%뿐입니다(현금 7.9% +
증권 급매). 나머지가 동시에 오면 무슨 수를 써도 지급할 수 없습니다.

### 결과 1 — 상전이

충격의 크기를 훑으면 5단계에서 본 것과 같은 모양이 나옵니다.

```
     충격 신호       파산확률       평균유출%
     0.100       0.00         0.0
     0.125       0.00        18.5
     0.150       0.10        37.6
     0.175       0.60        53.7
     0.250       1.00        61.3
```

"조금 나쁜 뉴스"와 "치명적인 뉴스" 사이의 경계는 연속적이지 않습니다.

### 결과 2 — 같은 은행, 같은 충격, 다른 결말 ← 이 단계의 핵심

임계점에서 seed만 바꿔 20번 돌리면 **12번은 파산하고 8번은 살아남습니다.**
대차대조표도 충격도 평균적인 성향도 전부 같습니다. seed가 바꾼 것은 누가
얼마를 맡겼는지, 누가 누구와 아는 사이인지, 누가 먼저 창구에 도착했는지 —
**우연뿐입니다.**

이것이 Diamond-Dybvig(1983)의 다중균형입니다. "아무도 빼지 않는 상태"와
"모두가 빼는 상태"가 둘 다 균형이고, 어느 쪽으로 굴러갈지는 예금자들이
서로를 어떻게 보느냐가 정합니다.

> **"SVB는 망하게 되어 있었나?"** 이 모형의 답은 "그렇다"도 "아니다"도
> 아닙니다. **망하기 쉬운 상태였지만, 망한 것 자체는 필연이 아니었습니다.**
> 4단계의 창발, 5단계의 상전이보다 한 걸음 더 나간 이야기입니다.

### 결과 3 — 무엇을 바꿨다면 막을 수 있었나

임계점에서 하나씩만 바꿔 본 반사실 실험입니다.

```
  시나리오                                    파산       평균유출%
  기준선 (SVB 근사)                          12/20        53.7
  [펀더멘털] 미실현손실이 없었다면              6/20        58.5
  [펀더멘털] 현금을 7.9%->20% 들었다면        12/20        55.1
  [펀더멘털] 현금을 7.9%->30% 들었다면        11/20        56.2
  [믿음] 예금보험 한도가 10배였다면             0/20        11.5
  [전파] 아는 사람이 8명->3명이었다면           4/20        51.5
  [전파] 남을 덜 따라했다면 (동조 절반)         0/20        13.5
```

효과가 세 단계로 갈립니다.

- **거의 없음** — 현금을 네 배로 늘려도 파산 횟수가 그대로입니다.
  런의 규모가 그보다 크기 때문입니다.
- **절반** — 미실현손실을 없애면 절반으로 줍니다. 무시할 수 없지만
  "해결"은 아닙니다. **건전한 은행도 런을 맞으면 죽습니다.**
- **차단** — 예금보험을 늘리거나 동조를 줄이면 0이 됩니다.
  잃을 것이 없는 예금자는 뛰지 않습니다.

즉 이 모형의 답은 "은행을 더 튼튼하게 만들라"보다 **"예금자가 뛸 이유와
서로를 따라 할 통로를 줄여라"**에 가깝습니다. 2023년 3월 12일 미국 당국이
SVB 예금을 한도와 무관하게 전액 보장한다고 발표해 확산을 멈춘 것도 같은
논리입니다.

다만 **이 결론은 이 모형의 규칙 안에서만 성립합니다.** 전액 보장이 만드는
도덕적 해이는 이 모형에 아예 없습니다. 모형이 답할 수 있는 질문의 범위를
넘지 않는 것도 실력입니다.

### 모형이 현실과 다른 지점

알고 쓰는 것과 모르고 쓰는 것은 다릅니다. 스크립트 마지막에 명시합니다.

- 증권이 즉시 팔린다고 가정했습니다. 실제로는 시간이 걸려서 SVB는 예금의
  24%만 지급한 시점에 문을 닫았습니다. **이 모형의 은행은 61%까지 지급하므로
  현실보다 관대합니다.**
- 중앙은행 긴급대출, 인수합병, 감독당국 개입이 없습니다.
- 다른 은행으로의 전염이 없습니다. 은행이 하나뿐인 세계입니다.
- 예금자의 판단 규칙이 실제 사람의 행동인지는 검증되지 않았습니다.
  **ABM에서 가장 약한 고리**이고, 그래서 극단 사례 검증과 반복 실행이
  필수적입니다.

## 관통하는 여섯 가지 원칙

1. **시뮬레이션 = 상태 + 규칙 + 반복 + 집계.** 1단계부터 5단계까지 동일합니다.
2. **결과는 숫자가 아니라 분포다.** 반복 실행하고 평균과 산포로 보고합니다.
   한 번의 실행값을 보고하는 것은 오류입니다.
3. **검증할 것을 먼저 정한다.** 이론값(MSD = 1.5t), 불변량(총액 보존),
   극단 사례(관용도 0이면 아무도 안 움직임). 이런 대조군 없이 얻은 숫자는
   모형의 결과인지 버그의 결과인지 구분할 수 없습니다.
4. **이론과 안 맞으면 어느 극한의 이론인지부터 확인한다.** 4단계의 0.5 대 0.667이
   그 예입니다. 유한 크기 효과는 버그가 아닙니다.
5. **지표를 맥락 없이 읽지 않는다.** 5단계의 관용도 0.875가 그 예입니다.
   수렴 여부를 함께 보지 않으면 정반대의 결론에 도달합니다.
6. **모형이 답할 수 있는 질문의 범위를 넘지 않는다.** 6단계가 그 예입니다.
   메커니즘의 설명과 예측은 다른 일이고, 숫자가 실제와 비슷하게 나왔을 때가
   오히려 가장 위험합니다.
